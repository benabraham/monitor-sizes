# Internationalisation (i18n) and formatting

How translations, language detection and locale-aware formatting work in Pixely a monitory,
how to add a key or a namespace, and what the tests guarantee. Contract signatures live in
[`ARCHITECTURE.md`](./ARCHITECTURE.md) (`i18n`, `lib/format.js`, `lib/units.js`); product
rules live in [`PRD.md`](./PRD.md) (F16, F20, UX "Key interactions", Calculation spec).

The UI ships in **Czech and English** (PRD: release gate). Czech is the first-class
language for copy quality: every key exists in both languages, enforced by a test.

## Files at a glance

```
src/i18n/
  index.js                  locale signal, detectLocale(), t(), getMissingKeys(), messages
  i18n.test.js              detection, t(), fallback, reactivity, parity across all namespaces
  locales/en/common.js      shared strings, English          (namespace: common)
  locales/cs/common.js      shared strings, Czech            (namespace: common)
  locales/en/metrics.js     metric labels and help, English  (namespace: metrics)
  locales/cs/metrics.js     metric labels and help, Czech    (namespace: metrics)
src/lib/
  format.js                 number, percent, resolution, scale, length, area, angle formatting
  units.js                  inch ⇄ cm and square inch ⇄ dm² conversion, unit labels, default distances
```

Message files are **discovered automatically**. `src/i18n/index.js` calls
`import.meta.glob('./locales/*/*.js', { eager: true })`, so nothing needs to be registered
by hand.

## Using translations in components

```jsx
import { t } from '../../i18n/index.js'

export const DeleteButton = ({ name, onDelete }) => (
  <button type="button" onClick={onDelete}>
    {t('common.delete')}
  </button>
)
```

- **Call `t()` where the text is rendered.** Components that call `t()` during render read
  the `locale` signal and re-render when the language changes. Do not cache translated
  strings in module-level constants, or in signals, because they then go stale on switch.
- **Use literal keys.** Write `t('metrics.ppi.label')`, never ``t(`metrics.${name}.label`)``.
  Literal keys can be found with grep, and the parity test can see them. If a metric key
  really is dynamic (the metric list is data-driven), enumerate the metric names in one
  place next to the code that uses them.
- **Do not build sentences from fragments.** Word order differs between Czech and English,
  so put the whole sentence in one message with `{placeholders}`:

  ```js
  // Bad: t('a') + ' ' + name + ' ' + t('b')
  // Good:
  t('common.deleteConfirm', { name })
  ```

- **Do not hand-format numbers or units in messages.** Numbers go through `lib/format.js`,
  and units come from `lib/units.js` (see below). A message can contain a placeholder for
  the result, such as `{value}`.

## Choosing the locale

`locale` is a signal from `@preact/signals`, initially `'en'`. The state layer
(`state/store.js`) owns the choice, using this precedence:

1. the `locale` in the URL hash (a shared link restores the sender's language, F16/F19);
2. the saved preference from storage;
3. `detectLocale()`, which reads `navigator.languages` by default.

```js
import { detectLocale, locale } from '../i18n/index.js'

locale.value = detectLocale() // only when no saved or URL locale exists
```

`detectLocale(languages?)` returns `'cs'` when any language tag's primary subtag is `cs`
(`cs`, `cs-CZ`, `CS-cz`). Everything else returns `'en'`. Note that `csb` (Kashubian) is
**not** Czech, because only the primary subtag counts.

Switching the language is `locale.value = 'cs'`. Nothing else needs to happen: every
component that calls `t()` during render updates.

## Adding a key

1. **Add the key to both files in the same change**, with the same nesting:
   `src/i18n/locales/en/<ns>.js` and `src/i18n/locales/cs/<ns>.js`.
2. Use the key in the component: `t('<ns>.<key>')`.
3. Run the tests. The parity test fails if either language is missing the key, if the
   placeholders differ, or if a value is empty.

Keys can nest. The file's default export is flattened into dotted keys:

```js
// locales/en/common.js
export default {
  units: { metric: 'Metric', imperial: 'Imperial' },
}
// → 'common.units.metric', 'common.units.imperial'
```

Name keys by what they are, not where they appear (`common.cancel`, not `dialogCancelBtn`).

## Adding a namespace

A namespace is one file per language, named after the feature. The file name (without
`.js`) is the namespace prefix. For a new `browse` feature:

```
src/i18n/locales/en/browse.js   export default { title: 'Browse', … }   → 'browse.title'
src/i18n/locales/cs/browse.js   export default { title: 'Procházet', … }
```

Both files are required. If the Czech file is missing, the parity test fails, because the
test discovers namespaces from the file list, not from a hardcoded list. Each feature owns
its namespace, so parallel work never edits a shared file.

Namespace names are lowercase, without dots (the dot is the key separator). A default export
must be a plain object, otherwise loading throws at import time, which is intentional: a
broken message file should fail in tests, not show raw keys in production.

## Message syntax

| Syntax                  | Meaning                                                                                                                 |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `{name}`                | Placeholder, filled from `t(key, { name })`. Non-string values are converted with `String()`.                           |
| `{name}` with no value  | Left as written (`Delete “{name}”?`), so the gap is visible in the UI and in tests.                                     |
| Other braces, `{ }`     | Not special if they do not match `{word}`. Avoid them anyway, to keep the placeholder rule simple.                      |
| Typographic punctuation | Use the proper marks: `…` for ellipsis, `“ ”` for English quotes, `„ “` for Czech quotes, `–` or `—` where they belong. |

**Lookup order** for `t(key, params)`:

1. the message for the active `locale`;
2. the English message (so a partial translation never shows a blank);
3. the key itself (a visible signal that a key is missing; the parity test prevents this
   from shipping).

Lookups use own properties only, so keys such as `constructor` or `toString` return the key,
not an inherited function.

## Writing good Czech and English copy

**Czech**

- Use correct diacritics everywhere (`stejné`, `Zavřít`, `Načítání…`, `Čeština`). An ASCII
  fallback in a shipped string is a bug.
- Use the **impersonal or infinitive** style for actions and hints (`Kopírovat odkaz`,
  `Obnovit výchozí`), and avoid second-person verb forms (`dostanete`, `chcete`). The
  shared style avoids the formal/informal choice (`vy` / `ty`) entirely.
- Sentence case for labels and buttons (`Přidat displej`, not `Přidat Displej`).
- Decimal comma in running text, but never hand-write numbers. Use `lib/format.js`.
- Use `„…“` for quotation marks, and a non-breaking space before `%` and units (done for you
  in `lib/format.js`).
- The `same` label for signed zero is `stejné`. It is shown in place of `+0 %`.

**English**

- Sentence case, short labels, no exclamation marks.
- Use "Metric" and "Imperial" for the unit switch, and "Baseline" for the active reference
  display.
- Pick one spelling convention and keep it across the whole file. Match the existing copy
  before adding new strings.

**Both**

- Keep labels short (column headers in particular). Put the explanation in `help`.
- Keep the same placeholders in both languages. The parity test enforces this.
- Do not put emojis in copy.

## Metric labels and help texts

The `metrics` namespace holds one entry per metric in the PRD Calculation spec, plus the
angular and scaling metrics:

```
diagonal, ppi, relativePixelSize, aspect, resolution, width, height, widthDiff, heightDiff,
area, areaRatio, megapixels, megapixelRatio, logicalResolution, effectivePpi, workspace,
comfortable, horizontalFov, verticalFov, ppd, logicalPpd, sameSize, sameSharpness, sameTextSize
```

Each metric has two strings:

- `metrics.<metric>.label`: the short column header. **No unit**, because the unit follows the
  active system (cm or in, dm² or in²). The caller adds it:

  ```jsx
  <th>
    {t('metrics.width.label')} ({lengthUnitLabel(units)})
  </th>
  ```

- `metrics.<metric>.help`: one to three plain sentences for the help popover (F20). It
  replaces the old "halp" sheet. It explains the meaning and the direction of the
  value: for example, relative pixel size is negative for smaller, smoother pixels, and
  a signed difference is positive when the display is larger.

Help texts use the words "positive" and "negative" for signs, and "baseline" for the
reference display. They never use the internal names of the calculation.

## Formatting rules (`lib/format.js`)

Only the format layer rounds and formats. Calculation results stay raw. Every rounding uses
`round()` from `lib/math.js`, which rounds half away from zero, as Google Sheets does. This
matters: `Intl` rounds the binary double, so `1.005` would round down.

| Function                                                   | Example output                     | Notes                                                                                          |
| ---------------------------------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------- |
| `formatNumber({ value, locale, digits })`                  | `1,234.5` (en), `1 234,5` (cs)     | Fixed decimals. Cached `Intl.NumberFormat` per locale and digits.                              |
| `formatSignedPercent({ ratio, locale, sameLabel })`        | `+2 %`, `−58 %`, `same`            | `ratio` is a fraction (0.02 = 2 %). Rounds to whole percent. NBSP before `%`.                  |
| `formatSignedNumber({ value, locale, sameLabel, digits })` | `+2`, `−58`, `same`                | No space after the sign.                                                                       |
| `formatResolution({ width, height, roundTo })`             | `3840 × 2160`, `3070 × 1730`       | `roundTo: 10` rounds each side to tens (logical resolutions). No grouping, in either language. |
| `formatScale({ scale, locale })`                           | `125 %` (`1.25`), `110 %` (`1.1`)  | Scale factors are stored as factors, and shown as percent.                                     |
| `formatLength({ inches, units, locale, digits })`          | `60 cm`, `23.6 in`, `23,6 in` (cs) | Converts from inches. NBSP before the unit.                                                    |
| `formatArea({ squareInches, units, locale })`              | `49 dm²`, `757 in²`                | Whole units.                                                                                   |
| `formatDegrees({ value, locale })`                         | `45.2°`, `45,2°` (cs)              | One decimal, no space before `°`.                                                              |
| `formatAspect(aspect)`                                     | `16:9`, `“21:9”`                   | Approximate labels (`isApprox`) get typographic double quotes, as in the sheet.                |

The rules behind them:

- **Minus is U+2212 `−`**, never a hyphen-minus. Negatives in every formatter use it, and
  tests assert that no ASCII `-` appears.
- **Signed zero reads "same"**, never `+0 %` or `−0`. A value counts as zero when it rounds
  to zero at the precision shown, so `0.4` with `digits: 0` is "same". The `sameLabel` is
  passed in already translated (`'same'` / `'stejné'`). If it is omitted, zero shows as a
  plain `0`.
- **No-break space U+00A0** separates a number from `%` and from unit labels, so they never
  wrap onto separate lines.
- **Times sign U+00D7 `×`** joins resolutions, with normal spaces around it.
- **Non-finite values** (`NaN`, `±Infinity`) render as an em dash `—`. This keeps a broken
  calculation visible without showing `NaN`.
- **Locale grouping** comes from `Intl`. Czech uses a space-like group separator and a
  decimal comma. The exact separator character varies between ICU versions, so tests compare
  against `Intl` output or a pattern, never a hardcoded character.
- Resolutions are the exception: they have **no grouping in either language** (`5120 × 1440`),
  which matches how people write them.

Typical call sites:

```js
formatSignedPercent({
  ratio: row.relative.areaRatio,
  locale: locale.value,
  sameLabel: t('common.same'),
})
formatScale({ scale: 1.25, locale: locale.value }) // '125 %'
```

Pass `locale` explicitly. The formatters are pure, so they do not read the signal themselves.
Components pass `locale.value` (which subscribes them to the change).

## Units (`lib/units.js`)

Values are stored **canonically**: lengths in inches, areas in square inches. Conversion
happens only at the display and input edges, so switching systems never accumulates rounding.

| Function                                          | Behaviour                                                |
| ------------------------------------------------- | -------------------------------------------------------- |
| `toDisplayLength({ inches, units })`              | cm (metric) or in (imperial)                             |
| `fromDisplayLength({ value, units })`             | back to inches, for values typed in the active system    |
| `toDisplayArea({ squareInches, units })`          | dm² (metric) or in² (imperial). 1 in² = 0.064516 dm²     |
| `lengthUnitLabel(units)` / `areaUnitLabel(units)` | `'cm'` / `'in'` and `'dm²'` / `'in²'`. Not translated.   |
| `DEFAULT_DISTANCE`, `defaultDistanceFor(display)` | 60 cm for monitors, 45 cm for laptops (stored in inches) |

Notes:

- **Diagonal and PPI stay in inches in both systems.** That is industry convention, so the
  diagonal input is always inches, and the diagonal label is never converted.
- **Any unit value other than `'imperial'` is metric.** That is the default (F16).
- Angles are always degrees. They never convert.
- Unit labels are not translated: `cm`, `in`, `dm²` and `in²` are the same in both languages.

## Tests and the parity guarantee

Run them with the owned suites:

```sh
pnpm vitest run src/lib/units src/lib/format src/i18n
```

What each suite guarantees:

- **`src/i18n/i18n.test.js`**
  - `detectLocale`: Czech tags, case, a false friend (`csb`), empty lists, and reading
    `navigator.languages` by default.
  - `t`: default English, switching, interpolation (including missing and non-string values),
    the fallback chain, inherited-property safety, and reactivity (an `effect` re-runs on a
    locale switch).
  - `getMissingKeys`: reports keys the reference has but the locale lacks.
  - **Parity, for every namespace file found on disk:**
    - every namespace has a file in every language;
    - the flattened key sets are identical across languages;
    - every language uses the same `{placeholders}` as English for each key;
    - every value is a non-empty string.

    Namespaces come from `import.meta.glob`, so a namespace added later is covered without
    touching the test.
- **`src/lib/format.test.js`**: every formatter, in both locales, including the minus sign,
  NBSP and times-sign rules, the "same" rule (including `−0.001 → same`), rounding half away
  from zero, and non-finite input.
- **`src/lib/units.test.js`**: conversion factors, round trips, the no-drift check, unit
  labels, and default distances.

To see the parity test work, add a key to only one language file: the suite names the
namespace and the missing key.

Coverage: `src/i18n/locales/**` is excluded from coverage (it is data). `src/i18n/index.js`,
`src/lib/format.js` and `src/lib/units.js` are covered by the suites above.

## Checklist

When adding or changing copy:

- [ ] Key added to **both** `en/<ns>.js` and `cs/<ns>.js`, same nesting.
- [ ] Literal key in the component (`t('ns.key')`), no string concatenation for sentences.
- [ ] Placeholders are identical in both languages.
- [ ] Czech uses correct diacritics and avoids second-person verb forms.
- [ ] Column labels carry no units; units come from `lib/units.js`.
- [ ] Help text is one to three plain sentences, and matches the metric's sign convention.
- [ ] Numbers and units are formatted with `lib/format.js`, not in the message.
- [ ] `pnpm vitest run src/i18n` passes.
