# Architecture

This document is the **contract** between the modules of the app. Each module is built
and tested in isolation against the signatures below, so they can be developed in
parallel. If you change a signature, update this file in the same change.

Product requirements live in [`PRD.md`](./PRD.md). Requirement IDs (F1…F23) are referenced
throughout.

## Stack

| Concern              | Choice                                                                                                                                                                                  |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Build                | Vite 8, `base` = `/monitor-sizes/` (GitHub Pages project site)                                                                                                                          |
| UI                   | Preact 11 + `@preact/signals` (fine-grained reactive state, no classes)                                                                                                                 |
| PWA                  | `vite-plugin-pwa` (Workbox `generateSW`), `registerType: 'prompt'` without UI = new version on next launch                                                                              |
| Storage              | IndexedDB via `idb-keyval`                                                                                                                                                              |
| Unit/component tests | Vitest 5 + jsdom + `@testing-library/preact` + `fake-indexeddb`                                                                                                                         |
| E2E                  | Playwright (Chromium): onboarding, offline reload, manifest/installability                                                                                                              |
| Formatting           | Prettier (no semicolons, single quotes)                                                                                                                                                 |
| CSS                  | Plain modern CSS (custom properties, nesting, container queries, `:has()`), one file per component. Baseline 2024 only: **no** anchor positioning, no `interestfor`, no `field-sizing`. |

Budget (PRD, Non-functional): JS < 50 kB gzipped, 200 displays recalculated in < 16 ms.

## Code conventions

- Functional and declarative. **No classes.** Arrow functions, template literals,
  **no semicolons**.
- **RORO** (receive an object, return an object) for every function with 2+ params. Single
  param functions take the value directly.
- Guard clauses first, early returns, happy path last.
- Descriptive names with auxiliary verbs: `isComfortable`, `hasError`, `isLoading`.
- **Every export has a JSDoc block** (description, `@param`, `@returns`, an `@example` for
  non-trivial functions). Types are documented with JSDoc `@typedef`s; no TypeScript.
- Lowercase-dash file and directory names (`scaling-matrix/scaling-matrix.jsx`).
- Tests are colocated: `foo.js` → `foo.test.js`. Write the test first where practical.
- Canonical units: **lengths and distances in inches**, areas in square inches, scales as
  factors (`1.25`, not `125`). Convert only in the format layer.
- Never store derived metrics. A display record holds inputs only (F1).

## Data model

```js
/**
 * @typedef {object} Display              F1 — inputs only
 * @property {string} id                  stable slug, e.g. "27-4k-3840x2160"; custom: "c-<random>"
 * @property {string} name                human name, e.g. "4K", "MacBook Pro 14.2″"
 * @property {number} diagonal            inches
 * @property {number} width               native px
 * @property {number} height              native px
 * @property {'laptop'|'monitor'|'ultrawide'} [tag]
 * @property {boolean} [isCustom]         true for user-added displays
 */

/**
 * @typedef {object} FamiliarEntry        F2
 * @property {string} id                  display id
 * @property {number} distance            viewing distance, inches
 * @property {number} scale               OS scale factor used on it, e.g. 1.5
 */

/**
 * @typedef {object} Comfort              F7, F23
 * @property {'ppi'|'ppd'} mode           which rule is active (default 'ppi')
 * @property {number} minPpi              default 90
 * @property {number} maxPpi              default 105
 * @property {number} minPpd              default 37 (≈ 90 PPI at 60 cm)
 * @property {number} maxPpd              default 43 (≈ 105 PPI at 60 cm)
 * @property {number} minWidth            minimum logical width, px, default 1024
 */

/**
 * @typedef {'windows'|'macos'|'linux'} PresetId   F21
 * @typedef {'metric'|'imperial'} Units             F16
 * @typedef {'en'|'cs'} Locale                      F16
 * @typedef {'height'|'width'|'diagonal'} SizeMatchBy
 */
```

Defaults: viewing distance 60 cm (23.622 in) for monitors and ultrawides, 45 cm
(17.717 in) for laptops; a display without tag counts as a monitor.

## `lib/calc` — calculations (wave 1)

All functions are pure. Inputs are raw (unrounded); outputs are raw. Rounding is the
format layer's job, except where noted.

### `geometry.js`

```js
/** @typedef {object} DisplayMetrics
 *  @property {number} ppi            √(w² + h²) / d
 *  @property {number} widthIn        w / ppi
 *  @property {number} heightIn       h / ppi
 *  @property {number} areaIn2        widthIn × heightIn
 *  @property {number} megapixels     w × h / 10⁶
 *  @property {{ label: string, isApprox: boolean, isMapped: boolean }} aspect
 */
getPpi({ width, height, diagonal }) → number
getDisplayMetrics(display) → DisplayMetrics

/** @typedef {object} RelativeMetrics   (vs the active baseline)
 *  @property {number} relativePixelSize   ppi_ref / ppi − 1
 *  @property {number} widthDiffIn         widthIn − widthIn_ref
 *  @property {number} heightDiffIn        heightIn − heightIn_ref
 *  @property {number} areaRatio           areaIn2 / areaIn2_ref − 1   (no ABS, PRD fix)
 *  @property {number} megapixelRatio      megapixels / megapixels_ref − 1
 */
getRelativeMetrics({ metrics, baselineMetrics }) → RelativeMetrics
```

### `aspect.js`

```js
getAspect({ width, height }) → { label, isApprox, isMapped }
```

Reduce `w:h` by GCD and map:

| Reduced       | label                                    | isApprox                        |
| ------------- | ---------------------------------------- | ------------------------------- |
| 16:9          | `16:9`                                   | false                           |
| 8:5           | `16:10`                                  | false                           |
| 7:3           | `21:9`                                   | false                           |
| 64:27, 43:18  | `21:9`                                   | **true** (rendered as `“21:9”`) |
| 32:9          | `32:9`                                   | false                           |
| 12:5          | `24:10`                                  | false                           |
| 21:10         | `21:10`                                  | false                           |
| 16:5          | `32:10`                                  | false                           |
| anything else | `(w/h).toFixed(2) + ':1'`, e.g. `1.55:1` | false, `isMapped: false`        |

### `scaling.js`

```js
/** @typedef {object} ScaleOption
 *  @property {number} scale               factor, e.g. 1.25
 *  @property {number} [looksLikeWidth]    macOS preset only
 *  @property {boolean} [isCustom]         user-added custom scale
 */
getScaleOptions({ display, presetId, customScales }) → ScaleOption[]
//  windows/linux: preset factors ∪ customScales, sorted ascending, de-duplicated
//  macos: for each looks-like width L: s = display.width / L, kept if 1 ≤ s ≤ 2
//         (rounded to 4 decimals), plus customScales; sorted ascending

/** @typedef {object} ScaledMetrics
 *  @property {number} scale
 *  @property {number} logicalWidth          w / s       (unrounded)
 *  @property {number} logicalHeight         h / s
 *  @property {number} effectivePpi          ppi / s
 *  @property {number} workspaceMegapixels   (w/s) × (h/s) / 10⁶   (s², PRD fix)
 *  @property {number} [logicalPpd]          ppd / s, only when distance is given
 */
getScaledMetrics({ display, metrics, scale, distance }) → ScaledMetrics

isComfortable({ scaled, comfort }) → boolean
//  mode 'ppi': minPpi ≤ effectivePpi ≤ maxPpi  AND logicalWidth ≥ minWidth
//  mode 'ppd': minPpd ≤ logicalPpd   ≤ maxPpd  AND logicalWidth ≥ minWidth
//             (false when logicalPpd is undefined)

/** @typedef {ScaledMetrics & ScaleOption & { isComfortable: boolean }} MatrixRow */
getScalingMatrix({ display, metrics, scaleOptions, comfort, distance }) → MatrixRow[]

getBestScale({ rows, comfort }) → MatrixRow | null
//  Among comfortable rows: the one whose effectivePpi (or logicalPpd in ppd mode) is
//  closest to the middle of the window; ties → the larger logical width.
//  No comfortable row: the row closest to the window (distance to nearest bound).
//  Empty rows → null.
```

### `angular.js`

```js
getFieldOfView({ size, distance }) → degrees          2 · atan(size / 2v)
getPpd({ ppi, distance }) → number                    ppi · v · π / 180   (v in inches)

/** @typedef {object} AngularMetrics
 *  @property {number} horizontalFov   degrees
 *  @property {number} verticalFov     degrees
 *  @property {number} ppd
 *  @property {number} logicalPpd      ppd / scale
 */
getAngularMetrics({ metrics, distance, scale }) → AngularMetrics

/** @typedef {object} EquivalentDistances   (inches)
 *  @property {number} sameSize        v_ref × L / L_ref, L = height|width|diagonal
 *  @property {number} sameSharpness   v_ref × ppi_ref / ppi
 *  @property {number} sameTextSize    v_ref × (ppi_ref / s_ref) / (ppi / s)
 */
getEquivalentDistances({ baseline, candidate, sizeMatchBy = 'height' }) → EquivalentDistances
//  baseline:  { metrics, distance, scale }
//  candidate: { metrics, scale }
```

Worked example (test fixture, PRD): baseline 24″ 1920×1080 at 60 cm, scale 1;
candidate 32″ 3840×2160 at scale 1.5 → sameSize ≈ 80 cm, sameSharpness ≈ 40 cm,
sameTextSize ≈ 60 cm.

## `lib/format.js` (wave 1)

All output uses `Intl.NumberFormat(locale)` (decimal comma in Czech) and the real minus
sign **U+2212** `−`. Rounding uses `round()` from `lib/math.js`. `sameLabel` is passed in
(translated by the caller: "same" / "stejné").

```js
formatNumber({ value, locale, digits = 0 }) → '1 234,5' / '1,234.5'
formatSignedPercent({ ratio, locale, sameLabel }) → '+2 %' | '−58 %' | sameLabel
//  percent = round(ratio × 100); 0 → sameLabel; NBSP (U+00A0) before '%'
formatSignedNumber({ value, locale, sameLabel, digits = 0 }) → '+2' | '−58' | sameLabel
//  rounds first; a value that rounds to 0 → sameLabel (PRD decision)
formatResolution({ width, height, roundTo = 1 }) → '3840 × 2160'
//  roundTo 10 → round({ digits: -1 }) on both sides: '3070 × 1730'; uses U+00D7 ×
formatScale({ scale, locale }) → '125 %'   (percent of factor, rounds to integer)
formatLength({ inches, units, locale, digits = 0 }) → '60 cm' | '23.6 in'
formatArea({ squareInches, units, locale }) → '49 dm²' | '757 in²'
formatDegrees({ value, locale }) → '45.2°' (1 decimal)
formatAspect(aspect) → '16:9' | '“21:9”' (quotes when isApprox)
```

## `lib/url-state.js` (wave 1)

The URL hash holds the full view state (F19), so a link restores the comparison.

```js
encodeState(viewState) → string          '#s=<base64url(JSON)>'
decodeState(hash) → Partial<ViewState> | null
```

Format: `#s=` + base64url (no padding) of UTF-8 JSON with **short keys** and a version
`v: 1`. Decoding validates every field (type, range, enum) and drops invalid ones; garbage
input → `null`; never throws. Custom displays referenced by the state are embedded as
inputs (`cd: [{ i, n, d, w, h, t }]`) so the recipient sees the same comparison
(decision). `ViewState`:

```js
/** @typedef {object} ViewState
 *  @property {'browse'|'compare'} view
 *  @property {FamiliarEntry[]} familiar
 *  @property {string|null} baselineId
 *  @property {string[]} compareIds
 *  @property {Record<string, { distance?: number, scale?: number }>} compareSettings
 *  @property {string[]} hiddenFamiliarIds        familiar displays hidden in Compare
 *  @property {Display[]} customDisplays          embedded custom displays
 *  @property {Units} units
 *  @property {Locale} locale
 *  @property {PresetId} presetId
 *  @property {number[]} customScales
 *  @property {Comfort} comfort
 *  @property {{ search: string, tags: string[], aspects: string[],
 *               minDiagonal: number|null, maxDiagonal: number|null,
 *               onlyComfortable: boolean }} filters
 *  @property {{ key: string, direction: 'asc'|'desc' }} sort
 *  @property {'physical'|'seen'} vizMode
 *  @property {SizeMatchBy} sizeMatchBy
 */
```

## `lib/storage.js` (wave 1)

```js
loadPersisted() → Promise<{ customDisplays: Display[], hiddenBuiltInIds: string[],
                            familiar: FamiliarEntry[], baselineId: string|null,
                            preferences: object, isOnboarded: boolean }>
savePersisted(partial) → Promise<void>      merges keys; swallows errors (PRD: never breaks)
clearPersisted() → Promise<void>
```

Uses one `idb-keyval` key per field under a custom store `('pixely', 'state')`. Corrupt or
missing data → defaults. IndexedDB unavailable → defaults, no throw.

## `i18n` (wave 1)

```js
locale           signal<'en'|'cs'>
detectLocale(languages = navigator.languages) → 'cs' | 'en'   any 'cs*' → cs, else en
t(key, params?) → string     'browse.title', params interpolate '{name}'; missing key → key
                             (reads locale.value, so components re-render on switch)
```

Message files are auto-discovered with `import.meta.glob('./locales/*/*.js', { eager: true })`.
`locales/en/browse.js` exports `default { title: 'Browse', … }` → keys `browse.title`.
**Each feature owns its namespace file(s)**, so parallel work never edits a shared file. A
test asserts that `en` and `cs` have identical key sets.

## Testing strategy

- `lib/**`: TDD, ~100 % coverage. The sheet snapshot (`data/sheet-snapshot/`) is the
  acceptance fixture: every row and metric must match the sheet's displayed values (with
  the PRD's documented fixes).
- Components: Testing Library, user-level behaviour (roles, labels), not implementation.
- E2E (Playwright, Chromium): first-run onboarding, compare flow, share link round trip,
  offline reload, manifest validity.
- `pnpm check` runs format check, tests with coverage thresholds, build and bundle size.
